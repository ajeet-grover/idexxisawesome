## The Product

Streakly — a consumer habit + micro-learning app. Users pick a track, do a 5-minute daily lesson, and build a streak; the streak is the core habit loop. Launched 4 years ago, Series B funded ($42M), 2.1M registered users, 340K MAU, growing 28% YoY on MAU.

**Core metric: Day-7 retention.** It slipped from 48% to 39% after the v2 streak redesign shipped.

Current focus: the **Streakly Comeback experience** — recovering that Day-7 retention drop.

### Key tension

The team already has a compelling candidate solution (a sketched "Comeback screen": best-streak stat, 60-second comeback lesson, one-tap streak-freeze — technically doable with existing data) before root cause is actually confirmed. The pull is to start designing/building that solution now; the discipline required is to first validate root cause from data and user feedback — is the retention drop driven by the streak reset itself, by notification tone/timing, or both, and how much does each contribute.

### Open decision

How to scope the Comeback experience once root cause is validated — targeting/eligibility logic (who sees it), streak-freeze rules (limits/cooldowns), and notification tone/timing are all still unresolved.
